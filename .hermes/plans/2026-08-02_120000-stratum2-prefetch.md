# Stratum2 Image Prefetch — Overlap CIFS Reads with GPU Compute

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.
> **Goal:** Stop the GPU from idling while the worker waits on CIFS image reads — prefetch the next images in a background thread so reads + PNG decode overlap with the current image's inference.
> **Architecture:** New `PrefetchReader` (bounded `queue.Queue` + background thread). Pipeline `process()` functions accept an optional preloaded BGR ndarray and skip their internal `cv2.imread` when given one. The orchestrator pulls preloaded images from the reader instead of reading inline.
> **Tech Stack:** Python `queue` + `threading`, NumPy, existing cv2/PIL pipeline.

---

## Problem Anatomy (measured this session)

Per-image critical path on both workers:

```
[1] _needs() stat ×2      → CIFS RTT (pose2.npy, seg2.npy)
[2] cv2.imread(raw/xxxxx) → CIFS RTT + ~1MB transfer + PNG decode   ← GPU idle here
[3] CPU: pipeline resize/pad + preprocessor
[4] GPU: DETR + Sapiens2 forward (~0.5–1s)                           ← only busy step
[5] CPU: UDP decode + coord transform
[6] np.save(...)          → CIFS RTT + transfer                      ← GPU idle here
```

Observed ~15 pose2/min ≈ 4s/image ⇒ GPU busy only ~20–40% of wall time. Also: an image requested for both `pose2` and `seg2` is currently **read from CIFS twice** (each `process()` calls `cv2.imread` independently).

## Proposed Change

### 1. New module: `src/stratum2/prefetch.py`

```python
class PrefetchReader:
    """Reads + decodes images ahead of the consumer in a background thread.

    Args:
        images: iterable of Paths, consumed in order.
        depth: how many images to read ahead (queue capacity).
        read_fn: callable(Path) -> np.ndarray | None (default cv2.imread).
    """
```

- Bounded `queue.Queue(maxsize=depth)`; background daemon thread fills it.
- Preserves order (queue semantics).
- Unreadable image → enqueue `None`; consumer falls back to its own read.
- `close()` / context manager stops the thread cleanly.
- `iter()` yields `(image_path, preloaded_bgr_or_None)` in order.

### 2. Pipeline signature change (all 5 modules)

`seg.py`, `normal.py`, `pointmap.py`, `matting.py`, `pose.py`:

```python
def process(image_path, output_dir, model, device, aspect_bucket=None, *, image=None):
    if image is None:
        image = cv2.imread(str(image_path))  # fallback
    ...
```

Backward compatible — existing callers (and all unit tests) still work.

### 3. Orchestrator: `src/stratum2/orchestrator.py`

- Build `PrefetchReader(images, depth=8)` at loop start.
- Replace `for i, image_path in enumerate(images)` with `for i, (image_path, preloaded) in enumerate(reader):`
- Pass `image=preloaded` to **all** Sapiens2 `process()` calls for that image.
- **Side win:** with both `pose2`+`seg2` requested, the image is read once and reused for both passes — halves CIFS reads on the strix.

### 4. Tests (TDD)

- bounded: never reads more than `depth` ahead of consumer
- unreadable image yields `None` (no crash)

## Expected Impact

- Hides CIFS read RTT + PNG decode entirely (steps 2–3 overlap step 4).
- Reuses one read across pose2+seg2 on the strix.
- Conservative estimate: **1.5–2× throughput** on both workers (pose2 and seg2).

## Risks / Notes

- **Memory:** depth 8 × ~5MB decoded = ~40MB — negligible.
- **Wasted reads:** images that turn out fully-skipped were read anyway; bounded by depth (≤8).
- **Crash safety unchanged:** artifacts still written synchronously; idempotency preserved.
- **Async writes** (step 6) are a separate follow-up — not in this change.
- **Thread-safety:** only the prefetch thread touches cv2.imread; torch/cuda stays on the main thread. No CUDA interplay.
